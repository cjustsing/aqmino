# 客户端与平台规划

`apps/` 每个一级子目录对应一个可独立构建、配置权限和发布的客户端。目录使用平台名，工程、target 和代码类型使用 `Aqmino`。

## 平台登记

| 目录约定 | 平台与职责 | 当前状态 | 复用方式 |
| --- | --- | --- | --- |
| `macos/` | Mac 菜单栏应用、设置、饮水记录、提醒 | 已创建目录骨架，待编码 | 本地 `AqminoCore` Swift 包 |
| `ios/` | iPhone / iPad 应用 | 规划路径，按需创建 | 优先复用 `AqminoCore`，独立 UI 与通知适配 |
| `watchos/` | Apple Watch 快捷记录与提醒 | 规划路径，按需创建 | 按能力复用核心包，独立生命周期 |
| `android/` | Android 应用 | 规划路径，按需创建 | 共用数据约定和样例，技术栈立项时确定 |
| `windows/` | Windows 桌面应用 | 规划路径，按需创建 | 共用数据约定和样例，技术栈立项时确定 |
| `web/` | 浏览器应用 | 规划路径，按需创建 | 共用数据约定和样例；单独验证后台提醒能力 |

以上是扩展位置，不代表已经承诺开发所有平台。iPad 初期归入 `ios/` 的同一工程，出现独立发布或工程需求时再拆分。

## 新增平台步骤

1. 明确该平台的最小使用流程、支持版本、通知和后台运行限制。
2. 创建对应目录与 README，放入该平台自己的工程、资源、测试和配置。
3. Apple 客户端评估核心包复用；其他平台先对齐 `shared/` 中的约定与样例。
4. 在该客户端内部实现存储、通知和生命周期处理，避免依赖其他客户端源码。
5. 补充该平台的验证方式和发布说明，并更新根 README 与本表。

跨端同步、账户和服务端在需求确定后单独设计。若需要后端，可新增根目录 `services/`；当前阶段不创建。
