# Aqmino · 水序 — 软件功能与设计方案

版本：v0.2｜日期：2026-10-10｜首个平台：macOS｜阶段：编码前设计。

水序是一款常驻菜单栏的喝水提醒工具：在用户选定的时段温和提醒，喝水后快速记录，并随时查看今日记录。首版围绕这条完整流程设计。

## 1. 设计依据与已确定方向

| 项目 | 依据与结论 |
| --- | --- |
| 产品 | 用户明确要做 Mac 喝水提醒软件，中文名「水序」，工程名 `Aqmino` |
| 风格 | 极简、精致、Apple 原生，中英文品牌 |
| 首版范围 | 用户本轮选择「提醒 + 快捷记录 + 今日进度」 |
| 视觉参考 | 用户喜欢并保留的[三张图标候选](../design/brand/icon-candidates/README.md)，最终图标尚待选定 |
| 界面主稿 | 用户选定第 3 套「紧凑秩序」，[细化稿](../design/macos/mockups/refined/README.md)补齐设置与菜单栏状态 |
| 工程基础 | 已有[目录规划](architecture.md)，目前没有应用源码、Xcode 工程或 Swift 包清单 |

本方案中的默认时段、间隔、容量按钮和界面尺寸是设计建议，可在实现与体验验证中调整。它们与用户已确认的首版范围分开记录。

## 2. 用户场景与体验目标

主要场景是长时间使用 Mac 工作时忘记喝水。用户需要在合适的时候看到提醒，完成一个快捷操作后回到工作，也能在会议或专注期间主动暂停。

| 场景 | 用户操作 | 预期结果 |
| --- | --- | --- |
| 开始使用 | 设定提醒时段与间隔，按需开启通知 | 清楚知道何时会收到第一次提醒 |
| 已经喝水 | 点击菜单栏中的容量按钮 | 保存一条记录，更新今日总量，重新计时 |
| 收到提醒 | 选择「记录 250 ml」或「10 分钟后」 | 直接完成记录或延后本次提醒 |
| 临时忙碌 | 暂停 30 分钟、1 小时或今日剩余时间 | 暂停状态可见，可随时恢复 |
| 查看今天 | 打开菜单栏面板或今日记录 | 看见总量、次数及自定目标的完成情况 |
| Mac 唤醒 | 回到工作 | 从恢复时刻重新计时，错过的提醒不会由应用集中补发 |

体验目标：记录常见容量只需打开面板并点击一次；暂停和恢复能从面板直接完成；状态说明始终回答「现在是否提醒、为什么、下一次何时」。首版通过实际操作验证这些目标，不预设未经测量的成功率。

下一版候选：最近 7 / 30 日趋势、历史补录与编辑、数据导出、多个提醒时段。更后续的平台或服务：iPhone / iPad、Apple Watch、跨设备同步与其他桌面平台。它们需要独立设计相应系统能力和数据行为。

首版范围不包含账户、云同步、体重推算目标、自动识别饮水、日历会议读取、其他应用活动监测、连续打卡奖励或社交功能。

## 4. 建议默认值与输入边界

| 项目 | 初始建议 | 可调整方式 |
| --- | --- | --- |
| 提醒开关 | 首次设置完成后开启；通知权限独立判断 | 全局开关 |
| 提醒日期 | 周一至周五 | 至少选择一天 |
| 每日时段 | 09:00–18:00，结束时刻不包含在内 | 同一天内的一个时段，结束晚于开始 |
| 间隔 | 45 分钟 | 30 / 45 / 60 / 90 分钟，或 15–180 的整数分钟 |
| 快捷容量 | 150 / 250 / 350 ml | 三个不同的正整数，每个 1–2000 ml |
| 自定义容量 | 用户自行输入 | 1–2000 ml 的整数，记录当前时刻 |
| 通知记录容量 | 初始 250 ml | 使用最近一次快捷或自定义记录容量；发送通知时固定按钮文案与容量 |
| 自定每日目标 | 初始关闭，面板显示总量与次数 | 开启时自行填写 1–10000 ml 的整数 |
| 达标后停止提醒 | 设置目标时默认开启 | 可关闭，关闭后保持时段提醒 |
| 通知声音 | 初始关闭 | 用户主动开启后，仍遵循系统声音设置 |
| 登录启动 | 初始关闭 | 用户主动开启，显示实际系统状态 |
| 数据保存 | 本机保存，已有记录保留至用户删除 | 今日记录删除或删除全部记录 |

容量与目标的数值边界用于输入校验；目标是用户自行选定的记录偏好。开启目标后才显示百分比和进度条。未设置目标时，「今日进度」表达今日累计记录，不显示一个人为预置的完成率。

时段长度必须长于提醒间隔，避免配置了时段却永远没有提醒。表单无效时展示对应字段说明，不保存无效设置。

## 5. 页面与信息层次

| 页面 | 首要信息与操作 | 打开方式 |
| --- | --- | --- |
| 首次设置 | 用途、提醒时段与间隔、下一次提醒预览、通知开启、可选目标 | 第一次主动打开应用 |
| 菜单栏面板 | 今日总量 → 提醒状态 → 记录按钮 → 暂停 / 恢复 → 今日记录与设置 | 点击水滴 |
| 自定义记录 | 容量输入、校验、记录与取消 | 面板「自定义…」 |
| 今日记录窗口 | 今日累计与时间倒序列表、删除及撤销 | 面板「今日记录」 |
| 设置窗口 | 提醒、记录与目标、通用、数据管理 | 面板「设置…」或应用活动时的快捷键 |
| 系统通知 | 一句简短提醒、明确容量的记录动作、稍后动作 | 提醒到期并具备相应通知能力 |

面板内保留一个清晰的主任务：记录饮水。详细设置使用独立窗口；今日记录也使用独立窗口，避免菜单栏面板持续变大。重复打开窗口时聚焦已有窗口。

详细组件、界面状态、文案与视觉规范见[macOS 交互设计](../design/macos/interaction-design.md)。

## 6. 完整使用流程

### 首次使用

1. 展示「在你选定的时段，温和提醒喝水」及菜单栏入口说明。
2. 展示建议时段与间隔，用户调整后立即看见下一次提醒预览。
3. 用户点击「开启通知」时才调用系统授权；选择「稍后设置」也可以进入面板记录饮水。
4. 每日目标为可选项；登录启动在设置中提供，不随首次设置自动启用。
5. 完成后打开菜单栏面板。再次启动不会重复引导，设置中可重新查看说明。

### 记录与反馈

1. 用户点击容量或填写自定义容量。
2. 保存期间相关按钮显示进行中，避免一次操作被重复提交。
3. 保存成功后更新今日累计，面板显示「已记录 250 ml · 撤销」10 秒。
4. 在允许提醒的状态下，从这次饮水时刻重新计算间隔；暂停与时段限制仍然有效。
5. 保存失败显示「未能保存，请重试」，累计与提醒时间保持先前状态。

### 提醒与忙碌

提醒使用普通系统通知，初始静音。正文建议「喝口水，稍作休息。」；动作是「记录 250 ml」与「10 分钟后」。点击通知正文打开面板，关闭通知不记录饮水。

暂停和全局关闭提醒都保留记录能力。暂停到期或手动恢复后重新计时；暂停期间喝水可以记录，但不会解除暂停。

普通通知的展示遵循系统专注模式和用户设置，实际交付并不保证准时；面板展示应用的计划时间。依据：[Apple 通知管理](https://developer.apple.com/design/human-interface-guidelines/managing-notifications)、[User Notifications](https://developer.apple.com/documentation/usernotifications/)。

### 今日目标

目标关闭时展示总量和记录次数。目标开启时额外显示「已记录 / 自定目标」与进度；超过目标继续显示实际总量，进度条最高显示 100%。达标后停止提醒开启时，状态变为「已完成自定目标，今日提醒已停止」。下一本地日期重新计算。

## 7. 提醒规则摘要

| 事件 | 首版行为 |
| --- | --- |
| 应用在时段开始前运行 | 首次提醒为时段开始 + 一个间隔 |
| 在时段中启动且没有未来有效计划 | 从启动时刻重新计时 |
| 记录当前饮水 | 重新计时，暂停和全局关闭保持不变 |
| 暂停 / 恢复 | 暂停期间不主动发提醒；恢复后经过完整间隔再提醒 |
| 稍后 10 分钟 | 仅延后本次有效提醒；超出时段后等待下一有效时段 |
| 未响应提醒 | 下一次按正常间隔计算；不加快频率，每次替换旧的本应用提醒 |
| 睡眠 / 唤醒 | 睡眠停止应用调度；唤醒重新计时，错过周期不补发 |
| 已达到目标且开启停止提醒 | 当天停止；记录仍可继续 |
| 通知拒绝或展示方式受限 | 清楚提示实际能力，记录照常可用 |
| 退出应用 | 停止后续周期；下一次启动恢复偏好和记录 |

准确的时间算法、优先级、通知动作和验证例子以[提醒规则](reminder-rules.md)为准。

## 8. 视觉与原生体验

界面建议沿用第三张候选的浅青绿与深青色气质，作为强调色探索方向；三张图片继续保留为应用图标候选。主要界面使用系统背景、字体、输入控件、分隔与焦点状态，品牌色集中用于主要操作和进度。

菜单栏使用单色符号，独立于彩色应用图标。状态同时有文字说明；暂停、错误或完成状态不依赖颜色辨认。中英文长度变化、深浅色、高对比度、键盘操作、VoiceOver 和减少动态效果需要在界面验收中验证。

## 9. 技术与实施安排

建议首版基线为 macOS 13+，以 SwiftUI 为主，AppKit 封装窗口与系统事件，UserNotifications 交付本地提醒。业务模型和时间规则放入 `AqminoCore`，数据先使用版本化本地文件，具体接口、文件映射和验证条件见[技术设计](technical-design.md)。

实施顺序：先验证菜单栏、窗口、通知动作、登录启动和睡眠事件；再实现记录与可靠保存；随后接入提醒规则；最后完成原生体验和发布验证。这样能在大量界面工作前发现系统能力问题。

当前机器的开发工具指向 Command Line Tools，应用构建前需要配置完整 Xcode。Bundle ID 与签名身份在创建工程或发布配置阶段填写，不影响本方案的功能定义。

## 10. 设计交付与下一阶段

本轮交付四份互相引用的方案：本页是功能范围与入口；交互设计定义用户可见状态；提醒规则定义时间与状态转换；技术设计提供模块、数据、验收标准及风险处理。

当前已完成设计、主稿选择、其他三个设置页与十八种菜单栏状态的[高保真细化稿](../design/macos/mockups/refined/README.md)，并检查文案、示例时间和文档一致性。应用构建、真实系统提醒、睡眠恢复和辅助功能验证将在实现阶段执行，验收条件已经列入技术设计。

进入编码时先完成[编码路线](roadmap.md)中的 M1 验证，再按 F-01 至 F-10 实施首版流程。
