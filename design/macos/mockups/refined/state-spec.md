# 水序 macOS 状态与交互规格

版本：v0.2｜日期：2026-10-10｜视觉主稿：[第 3 套](../03-compact-overview.png)｜界面入口：[细化稿](README.md)。

## 1. 共用布局

面板始终以「品牌 → 今日累计 → 提醒状态 → 快捷记录 → 暂停或当前操作 → 今日记录与设置」呈现。状态变化优先替换原有提醒区域，不另开重复状态卡片。累计数值使用系统正文色，青色用于可用的主要操作；禁用控件使用系统次要色。数据错误的图标和文字共同表达原因，不能只依靠颜色。

沿用面板宽 360 pt、最大高度约 560 pt和设置窗口 640 × 520 pt 的逻辑尺寸起点。内容超出时允许原生滚动；不通过压小字体或裁切文本硬塞。原稿画布像素和逻辑尺寸不能等同，原生排版阶段以真实系统控件验证。

## 2. 设置页

| 页面 / 状态 | 内容与控件 | 保存及系统行为 |
| --- | --- | --- |
| 记录与目标 / 关闭 | 三个容量输入 150 / 250 / 350 ml；目标开关关闭；目标值和达标停止开关折叠 | 容量为 1–2000 ml 不同整数；偏好保存后生效 |
| 记录与目标 / 开启 | 用户填写 1500 ml；达标后停止提醒开启；说明仍可记录 | 目标为 1–10000 ml 整数；首次开启不自动代填示例的 1500 ml |
| 通用 / 默认 | 登录启动实际状态关闭；外观和语言跟随系统；当前简体中文 | 系统操作立即生效，不由取消反向撤回；无业务草稿时保存禁用 |
| 通用 / 待批准 | 登录启动仍未实际启用；「需要系统批准」；「打开系统设置…」 | 返回后读取实际系统状态，批准前不虚报开启；失败也不先置为成功 |
| 数据 / 默认 | 本机保存说明；68 条演示记录；删除全部记录入口 | 无业务草稿时保存禁用；实际没有记录时禁用删除入口 |
| 数据 / 确认 | 标题「删除全部饮水记录？」；正文「将删除 68 条记录，且无法恢复。提醒设置会保留。」；取消和红色删除按钮 | 确认前不修改数量；取消关闭确认；确认后执行完整删除事务 |

设置业务偏好使用同一份草稿，切换分组保留未保存编辑；保存统一提交，取消放弃业务草稿。无效或正在保存的草稿不能提交。通知授权、登录启动和删除记录是独立操作，旁边或确认窗口说明实际效果。

容量和目标的空值、非整数、超出范围、容量重复均在对应字段下提示。关闭目标保留可恢复的既有用户值；开启后重新校验。跟随系统的外观和语言在当前首版是说明行，界面不提供额外主题或手动语言选择。

删除过程中禁用重复删除，显示「正在清理记录…」。删除意图尚未成功写入前失败，保留原数据并提示重试；意图已经写入后失败则显示「清理尚未完成，请继续完成」，恢复只继续事务，不能重新开放旧记录写入。全过程完成后才显示 0 条，不提供撤销全部清空。规则见[技术设计](../../../../docs/technical-design.md)。

## 3. 菜单栏十八种状态

以下顺序与[图片索引](README.md)各行的从左到右顺序一致；完整场景数据和标识保存在 [states.json](states.json)。

| 状态 | 今日累计 / 次数 | 状态文案与动作 | 界面约束 |
| --- | --- | --- | --- |
| 正常计时 | 750 ml / 3 | 下一次提醒 10:45；暂停提醒 | 容量点击即记录 |
| 记录成功 | 1000 ml / 4 | 下一次提醒 11:15；已记录 250 ml · 撤销 | 保存成功才增加；撤销 10 秒；面板保留 |
| 暂无记录 | 0 ml / 0 | 今天还没有记录；下一次提醒 10:45 | 正常记录入口可用，不显示目标百分比 |
| 暂停选项 | 750 ml / 3 | 30 分钟、1 小时、今日不再提醒 | 原生菜单锚定暂停行，取消不改状态 |
| 定时暂停 | 750 ml / 3 | 已暂停，11:00 恢复；恢复提醒 | 11:00 是恢复时间；到期后首次提醒为 11:45，时段资格仍需判断 |
| 今日暂停 | 750 ml / 3 | 今日已暂停；恢复提醒 | 本例周一，次日周二按工作日计划恢复 |
| 待授权 | 750 ml / 3 | 开启通知后接收喝水提醒；开启通知 | 点击才请求授权，打开面板不会弹权限请求 |
| 通知被拒绝 | 750 ml / 3 | 通知已关闭，仍可记录饮水；查看系统通知设置 | 记录可用，不再次伪造授权请求 |
| 仅通知中心 | 750 ml / 3 | 提醒将显示在通知中心；下一次提醒 10:45；查看系统通知设置 | 已授权且可向通知中心交付，不声称检测到专注状态 |
| 提醒关闭 | 750 ml / 3 | 提醒已关闭；开启提醒 | 一个明确开启入口，关闭时没有暂停入口或倒计时 |
| 时段之外 | 750 ml / 3 | 下次提醒 周一 09:45；修改时段 | 本例周六；记录与暂停入口保留 |
| 目标达成 | 1500 ml / 6 | 目标已完成；今日提醒已停止；修改目标 | 仅本例开启自定 1500 ml；线性进度 100%；继续记录可用 |
| 稍后提醒 | 750 ml / 3 | 将在 10:40 再提醒 | 10:30 延后 10 分钟；仅本次有效机会可延后 |
| 提醒到期 | 750 ml / 3 | 喝口水，稍作休息。；10 分钟后 | 可见前台界面只显示应用内提醒；不叠加系统横幅 |
| 发送失败 | 750 ml / 3 | 提醒暂时未能发出；下一次提醒 11:15；查看提醒设置 / 发送测试通知 | 下一周期已保存，交付失败不连续重试 |
| 自定义记录 | 750 ml / 3 | 记录饮水；容量 200 ml；取消 / 记录 | 范围 1–2000 ml 整数；提交前累计和计划不变；modal 阻止背景操作 |
| 保存失败 | 750 ml / 3 | 未能保存，请重试；本次 250 ml 尚未记录。；重试 | 不显示 1000 ml；存储恢复前禁用新增记录、自定义和暂停；保留已确认累计 |
| 读取失败 | — / 未知 | 记录暂时无法读取；重新读取 / 恢复有效备份 | 不显示虚假 0；禁用记录、自定义、暂停和今日列表，保留设置与恢复入口 |

保存失败时，原持久化计划仍是 10:45，但可靠写入恢复前暂缓调度，因此主状态不显示一个正在运行的倒计时。重试同一个未保存请求，只有保存成功后才发布新累计并按当前资格重新计时。读取失败恢复按钮只在已经验证有可用备份时出现；不存在可用备份时保留重新读取和设置入口。

暂停、总开关关闭、权限不足、时段之外、目标达成都不阻止记录。数据读写不可靠具有更高优先级，阻止依赖可靠持久化的操作。多状态并存时遵循[提醒资格优先级](../../../../docs/reminder-rules.md)，权限问题可以作为补充说明保留。

## 4. 示例时间的一致性

- 日期锚点是 2026-10-10 周六；正常工作时段的模拟日期是下一工作日 2026-10-12 周一，当前时刻 10:30。
- 正常计时最后记录在 10:00，下一次 10:45；成功状态在 10:30 再记 250 ml，变为 1000 ml / 4 次和 11:15。
- 空状态在 10:00 启动，没有记录，下一次仍为 10:45。
- 稍后、到期和交付失败的例子最后记录在 09:45，到期为 10:30。10 分钟后为 10:40；正常下一周期为 11:15。
- 定时暂停在 11:00 到期，恢复后再经过 45 分钟。手动提前恢复则从实际恢复时刻重新计时。
- 周六时段外的下一次是 2026-10-12 周一 09:45；目标达成本日没有下一次提醒。
- 所有数字都是设计示例数据，不代表用户已有实际饮水记录。

## 5. 图稿与实现检查

本轮已目视检查标题、中文主文案、数值与次数、提醒时间、目标开关、删除后果、恢复动作以及禁用控件，并对两张稿做定向修订。项目内的最终原图按字节复制，提示词和校验值均保存。

静态稿不验证真实键盘、VoiceOver、窗口行为或系统授权。原生实现时仍需按[技术验收](../../../../docs/technical-design.md)进行辅助功能、深浅色、显示缩放和系统能力验证；控件焦点顺序与视觉顺序一致，所有状态均有文字表达。
